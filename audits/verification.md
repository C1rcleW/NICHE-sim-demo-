### 1.1 发断数值（成立，逐位一致）

```
solve_model(competition_square_law, y0=[1.0,0.8], t=linspace(0,119,120), params=[0.3,0.25,0.5,0.4])
```

机理独立复算：系数矩阵 `[[0,-α],[-β,0]]` 特征值 `np.linalg.eigvals → [0.27386128, -0.27386128]`，
`√(αβ)=√0.075=0.273861` → **不稳定鞍点**，与报告一致。
边界极值测试（均在 `(1e-4,5.0)` 内）：

| α | β | eps | R1[-1] |
|---|---|---|---|
| 5.0 | 5.0 | 1e-4 | 2.5425e+257 |
| 1e-4 | 1e-4 | 1e-4 | 1.0024e+00（**不发散**）|
| 5.0 | 1e-4 | 1e-4 | −1.2726e+03 |
| 1e-4 | 5.0 | 1e-4 | 7.1959e+00 |

**对措辞的修正**：边界 `(1e-4, 5.0)` **并不"迫使"发散**——`α=β=eps=1e-4` 时增长率 `e^{1e-4·119}=1.01197`，
轨迹完全有界。**"必然发散"只在"α、β 不过小"时成立，且拟合器确实经常落到大 α/β**。
报告自己在 §5.1 写的是"结构性发散"，比断言里的"边界内必然发散"更准确；
`ε≥1e-4>0` 的作用是**取消良好设定的 ε=0 情形**、并在长时间下仍保留常激励，不是发散的充分条件。

### 1.3 证伪：`fun=602.966` 的参数"全部贴边"是错的

报告 §P1 原文给出的参数为 `alpha=0.0999, beta=0.0858, eps1=2.5739, eps2=2.4170`，
并称"（全部贴边）"。对这四个数逐一计算到边界的距离：

```
alpha = 0.0999   到上界 5.0 距离 = 4.9001   到下界距离 = 0.0998  -> 内点
beta  = 0.0858   到上界 5.0 距离 = 4.9142   到下界距离 = 0.0857  -> 内点
eps1  = 2.5739   到上/下界距离 = 2.4261/2.5738                  -> 内点（正中）
eps2  = 2.4170   到上/下界距离 = 2.5830/2.4169                  -> 内点（正中）
```

**四个参数没有一个是边界点**。报告把 `α≈β≈0.09` 描述为"贴边"，
是把"接近下界的方向"与"位于边界上"混为一谈——L-BFGS-B 的边界是**硬约束**，
内点解与贴边解在诊断含义上完全不同（贴边 = 被边界截断，内点 = 真正的驻点）。
我在同一数据上直接验证：该组参数在 `state_happiness/state_stress` 映射下的 `_objective` = **2883797.21**，
预测轨迹 R1 ∈ [−7.91e3, 24.38]、R2 ∈ [0.30, 7.38e3]，而数据仅在 0.25–0.49 / 0.30–0.95 →
**真实（未截断）R² = −2.4977e+08**。这些数字说明该解是"爆炸轨迹的驻点"，而不是"被边界钉住"。

### 1.4 证伪：报告自己的两个量级不一致

同一份报告里，同一模型 `square_law`：

- §P1：`success=True, fun=602.966, R²=0.0`，参数 `α=0.0999, β=0.0858, ε=2.57/2.42`（**大 `fun` 分支**）；
- §P3：`_objective([0.3,0.7,0,0]) = 3.172e44 > 1e12`，并称"优化器被驱向求解失败平台"。

若优化器真的会被驱向"失败平台"（`1e12`），它就不可能停在 `fun=602.97` 这个**远低于 1e12 的有限平台**上。
我的实测支持后一种（有限平台）而不是前者：在同一个 Father 数据、同一映射上，
`_objective(报告参数) = 2.88e6`，而 `_objective([0.3,0.7,0,0]) = 3.17e44` 量级的失败平台**确实存在**

两个现象可以共存，但报告未区分"爆炸但有有限 MSE"与"求解失败得 1e12"两种平台，
导致 `fun=602.966` 被当成唯一结论，而它只是特定数据/种子/映射下的一个取值。

## 2. V2 — wellbeing 的 `p`/`income` 不可辨识

### 2.1 结构检查（成立）

`lanchester.py:44-52` 源码（我为验证而读取）中 `p` 与 `income` **仅以 `p * income` 出现在第一行 RHS**：

```python
return [p * income - q * S * H, r * H * (1 - S) - s * S]
```

`income` 不出现在任何其他项（含 `dS/dt`），因此对任意 `λ>0`，
`(p, income) → (λp, income/λ)` 保持 RHS 逐点不变 → **ODE 解与目标函数严格不变**。

### 2.4 实际后果（成立，且有比报告更强的直接证据）

`fit_robust(wellbeing, agent_id=Father)` → `p=0.094275, q=0.064411, r=0.112646, s=0.001124, income=0.179184`
→ 乘积 `p·income = 0.016893`、`R² = 0.950314`。
把 `income` 用 `make_fitter('wellbeing', income=...)` 固定后重拟合：

| 固定 income | 拟合 p | p·income | R² | fun |
|---|---|---|---|---|
| 0.0001 | 5.000000 | 0.000500 | 0.924774 | 1.233182e-03 |
| 0.5 | 0.033785 | 0.016892 | **0.950314** | **8.145090e-04** |
| 5 | 0.003378 | 0.016892 | **0.950314** | **8.145090e-04** |

固定 `income=0.5` 与 `income=5`（相差 10 倍）时 `R²` 与目标函数**逐位相同**——
这是"被识别的是乘积、不是 `p` 或 `income`"的直接证明；
而被固定为 `1e-4`（乘积偏离 33 倍）的 R² 仍高达 0.9248，说明**损失面在乘积方向极度平坦**。
`summary_json()` / `/api/fit` 会把 `p` 与 `income` 两个数分别展示，用户无从得知其中一个是任意的。

### 2.5 V2 判定

**成立**。唯一需要提醒的是：报告的绝对目标函数值、绝对 SVD 数值与 rank 计数依赖其自身数据/差分约定，
不能跨数据集引用；但"只以乘积出现 / 族内逐位相同 / 雅可比秩缺（σ_min 数值零）"
三条**命题本身全部独立复现**。严重度 P1 恰当（它是数学上的精确不可辨识，而非数值病态）。

## 3. V3 — 健康校准崩溃

### 3.1 机理与量级（成立）

`family_member.py:113-120`：`hp_change = -(base_decay + age_decay·age·(1−edu_protect))·dt_months`，
默认 `base_decay=0.002, age_decay=0.00015, edu_protect=0.30, dt_months=1.0`：

```
edu=1.0 时月损失 = 0.002 + 0.00015·age·0.70
edu=0.5 时月损失 = 0.002 + 0.00015·age·0.85
age=30: 0.002+0.00450·0.70=0.00515 … age=40: 0.0062 … age=50: 0.00725
```

与实测 60 个种子的平均月损失 **0.006421** 吻合 → 从初始 `health≈0.897` 到 `0.01` 约需
`0.887/0.0065 ≈ 137` 步，即**约 11.4 年**。这是 P1 级别的校准错误，**机理成立**。

### 3.2 确定性复现（成立，与 41.8 差 0.13 岁）

```
randomness=0，起始 30 岁，1 步/月，700 步：
  首次 health<=0.01 于 step 140，年龄 41.67，health=0.0100000000
  初始 health=0.905682（对应"30 岁 → 90.6%"，公式 1−0.003·30=0.91）
报告 H2：30 岁 → 41.8 岁
```

同一脚本对 20/40/50 岁的复现：**34.42 / 49.75 / 58.42**（报告 34.6 / 50.3 / 58.2）。
差异 0.1–0.5 岁来自 education 初值的随机抽样（影响 `decay_age` 项的折扣），属种子差异，**量级一致**。

### 3.3 但断言里的两个"里程碑"都不是必然事件（需修正）

**(a) "120 步后 health<0.2"**：60 个种子（默认 `randomness=0.02`）实测：

```
final health: mean=0.1264  sd=0.0697  min=0.0100  max=0.3125
health<0.2 的比例 = 81.7%  (49/60)      <-- 不是 100%
health<0.1 的比例 = 36.7%
```

→ 约 **1/5 的运行在 120 步后 health 仍 ≥ 0.2**（最高到 0.3125）。
"120 步后 health<0.2"是**高概率事件而非定律**。

**(b) "30 岁触底 0.01（约 42 岁）"**：默认 `randomness=0.02` 下，
120 步内真正触底的比例只有 **10.0%（6/60）**——因为触底需要约 137 步，
而 120 步只走到 40 岁。即便延长到 140–150 步，随机游走项 `N(0, 0.006)` 的累积
也使触底时刻在 120–140+ 步间抖动。
"约 42 岁触底"只在 **`randomness=0`** 的假设下严格成立；报告正文与附录虽写了"随机性=0"，
但断言与 P1 标题句未带该限定，容易被读成"默认参数下必触底"。

**反证示例**（默认参数、可复跑）：`random.seed(1)`、单成员 30 岁、120 步 →
`final_health=0.165922`（<0.2 ✓ 但远未触底）；`random.seed(42)` → `0.087804`。
即同一"默认参数"下，读者的复现结果会在 0.09–0.31 之间随机分布。

### 3.4 V3 判定

**部分成立**。健康衰减量级失控（P1）**成立且可由解析式+实测双重确认**；
但断言中"触底约 42 岁"与"120 步后 <0.2"把**确定性结论与随机场景的期望混合叙述**，
未标注 `randomness=0`，导致可复现性表述过强。
建议表述修正为："`randomness=0` 时 30 岁在 41.7±0.3 岁触底；
默认随机性下 120 步末有 ~82% 概率 <0.2，但仅 ~10% 概率已触底。"

## 4. V4 — `extract_features` 标签处理

### 4.1 独立 ground-truth 方法

我没有复用报告的脚本，而是：
1. 自建面板（2 户 5 成员 + 2 Household，240 步 → `df.shape=(1680,20)`，`agent_type` 计数
   `{'FamilyMember': 1200, 'Household': 480}`）；
2. 用 `lookup = {(agent_id, time): state_happiness}` 建字典，再逐行查
   `lookup[(r.agent_id, r.time + 1)]` 生成**位置对齐的真值数组**；
3. 与 `df.groupby("agent_id")["state_happiness"].shift(-1).fillna(0).values` 逐位置比较。

### 4.2 (a) 伪造 0（成立，数字与报告完全一致）

```
y == 0.0 的行数                 : 485 / 1680 = 28.869%
其中"无真实下一步"的行           : 485   <-- 全部是伪造
其中"真值确实是 0.0"的行         : 0
无真实下一步却拿到非零标签的行   : 0
按 agent 分组的末行（NaN→0）      : 7 行（7 个 agent）
Household 行（state_happiness 全 NaN）: 480 行
480 + 7 结构性地 = 487? 实测 485（2 个 Household 末行与 agent 末行重合）
```

485/1680 = **28.869%**，与报告 **28.9%** 一致；且我额外证明了
**"这 485 个 0 没有一个对应真实 0"**——即全部是 `fillna(0)` 伪造，
而非"数据里本来就有静止的 0"。这比报告更进一步地把"伪造"与"合法"分离开。

### 4.3 (b) 原生顺序位置一致（成立）

| 面板变体 | 错位 / 有真实下一步的行 |
|---|---|
| native 录制顺序（step-major，agent 交错） | **0 / 1195** |
| `sort_values(["agent_id","time"])` | **0 / 1195** |
| `sort_values(["time"])` | **0 / 1195** |
| `df.sample(frac=1, random_state=0)` | **1190 / 1195（99.6%）** |
| `df.iloc[::-1]` | **1195 / 1195（100%）** |
| `pd.concat([df, df], ignore_index=True)` | 0 / 2390 |

→ `groupby(...).shift(-lag)` 返回的 index 顺序 == `df` 行序（我实测 `list(s.index[:5]) == list(df.index[:5])` 为 True），
因为 `X = df[feat].values` 用的是**行位置**，所以 native/排序顺序下**恰好正确**——
报告"Lead 原线索 1（跨 agent 边界错位）被证伪"的结论**成立**。

### 4.4 (c) 打乱即静默错位（成立，但报告低估严重度）

打乱后错位率 **99.6%（1190/1195）**，报告中为 **113/116 = 97.4%**（Lead 146/150 = 97.3%）。
两者都远高于"0"，方向一致；但我的面板更大、错位更接近 100%——
说明这个缺陷不是"偶尔错位几十行"，而是**行序一旦变化，标签几乎全错**。
错误量级（我抽 5 行举例）：

```
row 0: agent=aa18599d t=146  y_claimed=0.3025  TRUE next(t=147)=0.2366  |err|=0.0659
row 1: agent=c542bf3d t=185  y_claimed=0.3996  TRUE next(t=186)=0.2088  |err|=0.1908
row 2: agent=aa18599d t=86   y_claimed=0.4663  TRUE next(t=87)=0.3028   |err|=0.1634
错位行平均绝对误差 = 0.0993 ;  target 标准差 = 0.0988
```

**平均误差 ≈ 目标信号的一倍标准差** → 错位标签的监督信息基本被抹平为噪声，
且**无任何异常/告警**。这是真实 P1 隐患，报告定性正确。

### 4.5 (d) 截断 no-op（成立）

```
len(y) = len(X) = 1680
`[:len(X)]` 是否改变数组: False
`X[:len(y)]` 同理为 no-op（len 相等且已同步）
```

`shift` 返回的是**全长度** Series（NaN 已被 `fillna(0)` 填掉），故切片永远不生效。
它制造了"已经对齐/去尾"的错觉，实际既不修对齐也不去尾，**误导性成立**。

### 4.6 V4 判定

**成立**（(a)(b)(d) 与报告逐位一致；(c) 方向一致且实际更严重）。
唯一修正：`pd.concat` 追加自身的构造在我的面板上**并不错位**（0/2390），
报告"错位 3 处"依赖其特定拼接方式，不具普遍性。
